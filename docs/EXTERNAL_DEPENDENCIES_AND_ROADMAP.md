# 外部依赖、技术演进与二期路线图

本文是生产上线和采购立项的边界清单。仓库中的 Mock 数据、OAuth 桩、Webhook 桩和本地发送器仅用于开发验收，不构成真实商业服务、账号、授权数据或送达率承诺。

## A. 需要采购或申请的真实资源

| 依赖 | 用途 | 获取方式 | 当前代码能力 | 上线准入证据 |
|---|---|---|---|---|
| 海关进出口数据（200+ 国家、5000+ 产品） | 商机洞察核心数据 | 商业授权或合作数据商 | Mock 生成器、CSV/JSON 导入和断点更新接口 | 授权合同、字段字典、覆盖率、更新频率、数据合规说明 |
| SMTP 发信域名与 IP | 邮件营销 | SPF/DKIM/DMARC 配置及发信服务商 | Mock 发送器、队列、追踪和域名自检脚本 | DNS 验证、IP 信誉、退信/投诉 Webhook、预热计划和送达测试 |
| Facebook Graph、LinkedIn、YouTube Data API | 发帖与互动 | 开发者账号、应用审核和 OAuth | Mock OAuth、适配器接口、异步发布及重试 | 应用审核、权限范围、回调域名、隐私政策和令牌轮换方案 |
| WhatsApp Business、Messenger、Skype | 即时通讯 | 对应平台商务/开发者接入 | 唤起链接和 Webhook 接收桩 | 商务账号、号码/页面绑定、签名验证和数据保留政策 |
| 跨境网络运营环境 | 学生实训网络环境 | 合规专线或跨境云第三方供应商 | 申请、审批、配置摘要、期限及到期提醒 | 服务合同、合规说明、交付 SLA、学生授权和应急联系人 |
| 40 个 Facebook/YouTube 实训账号 | 院校账号池 | 中标单位按协议分阶段开通 | 账号池、申请审批、分配、到期和归还 | 平台规则允许的开通方式、账号归属、实名责任、恢复与交接流程 |

### 采购依赖顺序

```text
数据与平台合规确认
  → 供应商选型及合同
  → 测试账号/沙箱接入
  → 预生产联调
  → 安全与隐私评审
  → 小范围试运行
  → 生产启用
```

不得用 Mock 结果证明真实海关覆盖、97% 邮件送达率、3 秒到达、社媒平台审核通过或账号长期可用。上述指标必须由真实供应商环境和正式授权账户重新验收。

## B. 推荐技术栈与迁移边界

| 层级 | 生产建议 | 当前仓库 | 演进方式 |
|---|---|---|---|
| 商店前端 | Next.js App Router、TypeScript、SSR/SSG、TailwindCSS | 零依赖静态 HTML/CSS/JS 和静态导出器 | 保留模板 JSON 协议与 URL，逐页迁移到 Next.js 渲染器 |
| 管理后台 | React/Next.js，可选 Ant Design，ECharts | `apps/admin` 原生页面和轻量图表 | 保持 API 契约，替换视图层，不改业务状态机 |
| 后端 | NestJS 或 FastAPI，REST + 异步消息 | Node.js HTTP API | 先抽离领域服务，再迁移控制器和持久层 |
| 业务数据 | PostgreSQL | JSON Store 演示 + SQL migrations | Repository 适配器切换 PostgreSQL，按 `tenant_id` 隔离 |
| 分析数据 | ClickHouse | Schema、物化视图和归档桩 | Kafka 批量消费写入 ClickHouse 集群 |
| 缓存/队列 | Redis Cluster + BullMQ；大规模事件用 Kafka | 内存缓存、队列执行器和 Kafka 架构配置 | 定时任务优先 BullMQ，跨域事件与海量数据使用 Kafka |
| 搜索 | OpenSearch/Elasticsearch | 内存检索服务和索引映射 | 双写索引、校验结果后切读流量 |
| 文件 | S3 兼容对象存储 + CDN | 本地发布目录和归档脚本 | 替换 Storage Adapter，启用版本控制与生命周期 |
| 部署 | Compose 演示 → K8s 生产 | Compose、Nginx、监控和灾备脚本 | 镜像化、HPA、PDB、跨 AZ 及 GitHub Actions |

选择 BullMQ 处理延时发送、导出、定时发布等 Redis 生态任务；选择 Kafka 承载询盘、社媒互动、CRM 时间线和海关增量等跨模块高吞吐事件。二者可并存，不应强行用一个队列覆盖全部场景。

## C. 二期增强路线图

### P1：AI 建站和商品内容助手

- 在装修器增加“AI 生成页面”和“批量生成多语言商品文案”。
- 输入必须包含品牌、市场、品类、语气和禁用词；输出仍保存为现有模板 JSON。
- LLM Provider 采用可插拔接口，无密钥时只返回明确标识的 Mock 内容。
- 上线前增加事实校验、敏感内容过滤、成本配额和人工确认。

### P1：收款配置向导

- 比较 PayPal、Stripe 和本地支付的支持地区、主体资质、结算及拒付风险。
- 提供资料准备、域名一致性、退款政策、物流证明和风控检查清单。
- 只做引导与状态记录；实际开户、KYC 和资金操作必须跳转官方渠道。

### P1：广告计划与 ROI

- 增加 TikTok、Facebook、Google 广告计划模板、预算和素材关联。
- 归集 UTM、广告花费、访问、询盘和订单，计算 CPA、ROAS 和 ROI。
- 正式读取花费前需申请对应广告 API 权限。

### P2：全渠道消息聚合增强

- 在现有社媒收件箱上扩展会话分配、SLA、快捷回复、内部备注和机器人转人工。
- 用平台事件 ID 保证幂等，保留消息来源和授权边界。
- 不以网页抓取替代官方 API。

### P1：轻量 B2B 询盘站

- 模板市场单列“工厂展示/定制询盘”，突出产能、认证、OEM/ODM、MOQ、交期和询盘表单。
- 支持产品目录无在线支付模式，以及附件和规格需求收集。
- 复用现有多语言、SEO、静态导出和 CRM 询盘链路。

## 里程碑建议

| 里程碑 | 范围 | 退出条件 |
|---|---|---|
| M1 真实数据与邮件 | 海关供应商、SMTP、域名认证 | 授权、更新、查询、发信、退信全链路通过 |
| M2 官方社媒 | Facebook/LinkedIn/YouTube/WhatsApp | 应用审核及发布、消息、Webhook 验签通过 |
| M3 生产技术栈 | PostgreSQL、Redis、Kafka、S3、OpenSearch | 双写校验、备份恢复、性能和安全验收通过 |
| M4 二期 P1 | AI、收款向导、广告、B2B 模板 | 院校试点、权限/配额、操作手册和效果指标通过 |
| M5 消息中心增强 | 全渠道会话工作台 | SLA、幂等、分配和审计通过 |

所有里程碑均应先在预生产使用非真实个人数据完成联调，再按灰度计划进入生产。
